# Единый установщик «Картотека» — подготовка выпуска

## Что исправлено в установочном сценарии

- Установщик PostgreSQL копируется в `{app}\installer\payload`, а не во временный каталог Inno Setup. Сценарий установки может найти его после копирования файлов.
- Пароли и email первого администратора вводятся в оконных диалогах Windows Forms, а не через консольный `Read-Host`.
- Ошибки сценариев показываются пользователю и записываются в журналы. Если PowerShell завершается с ненулевым кодом, Inno Setup пропускает страницу успешного завершения и возвращает ненулевой код.
- Журналы: `%ProgramData%\Kartoteka\Logs\server-install.log` и `%ProgramData%\Kartoteka\Logs\workstation-install.log`.
- Установщик PostgreSQL удаляется из каталога приложения только после успешной проверки службы. При сбое payload сохраняется для диагностики.
- Сценарий ждёт готовности PostgreSQL и сначала проверяет наличие базы/роли, чтобы не менять существующие объекты.

## Важное ограничение текущего архива

Этот архив **не является полным исходным проектом**. В нём отсутствуют каталоги `Data`, `Models`, `Controllers` и `Migrations` (или `migration`), а также `artifacts\publish`. `Program.cs` ссылается на `Kartoteka.Server.Data` и `Kartoteka.Server.Models`, а чистая установка требует полноценные EF Core migrations. Поэтому из содержимого данного архива нельзя собрать и подтвердить работоспособный установщик приложения.

Перед выпуском нужно восстановить полный исходный проект, проверить начальную миграцию для всей схемы, выполнить `dotnet publish`, затем прогнать `Check-ReleasePrerequisites.ps1` и собрать Inno Setup. Наличие PostgreSQL installer в `installer/payload` само по себе не подтверждает, что его unattended-параметры проверены на чистой Windows.

## Сборка на компьютере разработчика

Из корня полного проекта:

```powershell
dotnet publish Kartoteka.Server.csproj -c Release -r win-x64 --self-contained true -o artifacts\publish
.\installer\scripts\Check-ReleasePrerequisites.ps1 -ProjectRoot . -RequirePostgresPayload
& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' '.\installer\KartotekaSetup.iss'
```

Сборка должна остановиться, если отсутствуют опубликованная сборка или миграции. Не обходить эти проверки ради получения EXE.

## Проверка перед выпуском

1. Испытать чистую серверную установку на отдельной тестовой Windows 10/11 x64.
2. Убедиться, что мастер показывает запросы паролей; создана служба PostgreSQL, создана база `kartoteka`, создана и проверена служба `KartotekaServer`.
3. Открыть `https://<имя-сервера>:8443/health` и проверить, что возвращается HTTP 200.
4. Проверить запуск приложения после перезагрузки, создание первого администратора, подключение рабочего места и доверие сертификату.
5. Проверить поведение при занятом порте 5432, ошибочном пароле, отмене диалога и отсутствии payload.
6. Проверить удаление приложения с сохранением данных и отдельно проверить резервное копирование/восстановление.

Не использовать серверный сценарий для обновления существующей базы. Перед выпуском требуется подтверждённая процедура обновления и резервного копирования.
