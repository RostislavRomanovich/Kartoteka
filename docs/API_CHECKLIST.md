# Приёмочная проверка API (после сборки и миграции)

Проверить на тестовой БД, не на реальных персональных данных:

1. `GET /health` без токена возвращает healthy.
2. `GET /api/employees` без токена возвращает 401.
3. Вход с неверным паролем возвращает 401; в журнал попадает login_failed без пароля.
4. `viewer`: чтение и CSV разрешены; POST/PUT/DELETE сотрудников и любые запросы вложений возвращают 403.
5. `editor`: чтение, создание, редактирование и CSV разрешены; удаление и вложения возвращают 403.
6. `admin`: доступен полный CRUD и вложения.
7. После деактивации учётной записи нужно проверить стратегию отзыва уже выданного JWT: текущий токен живёт до 20 минут, поэтому для немедленного отзыва потребуется проверка версии безопасности/состояния пользователя на запросах либо короткоживущие токены с обновлением.
8. Проверить контракт: дата окончания автоматически рассчитывается от даты начала и срока, если дата окончания не задана.
9. Проверить CSV на кириллицу, открытие в Excel и формульную инъекцию.
10. Проверить, что ни в одном ответе карточки сотрудника нет содержимого вложений.

В текущем каркасе не реализованы тесты автоматизированно; этот список — ручной план приёмки.
