# Этап 10 — уведомления по срокам

## API

`GET /api/alerts` — возвращает актуальный список предупреждений для авторизованного пользователя с ролью `admin`, `editor` или `viewer`.

Каждый объект содержит стабильный `id`, тип, серьёзность, идентификатор сотрудника, ФИО, описание, дату срока и `highlightEmployeeName`. Клиентский интерфейс должен подсвечивать ФИО жёлтым цветом, если у сотрудника есть хотя бы одно предупреждение.

## Правила расчёта

- **Контракт:** используется `ContractEnd`; если он не задан, дата рассчитывается как `ContractStart.AddMonths(ContractTermMonths)`. Уведомление появляется за шесть календарных месяцев до даты окончания и остаётся видимым до исправления данных/обновления срока. Истёкший контракт имеет серьёзность `overdue`.
- **Водительская категория:** предупреждение появляется, когда дата окончания находится в пределах следующих 30 календарных дней, включая уже истёкшие даты.
- **Классность:** предупреждение появляется, когда `ReviewDueOn` находится в пределах следующих шести календарных месяцев, включая просроченные сроки.
- Архивные сотрудники исключаются.
- Статусы: `warning`, `due`, `overdue`.

Все сроки вычисляются на каждый запрос по текущим данным. Уведомления не записываются в базу, поэтому повторные запросы не создают дубликатов, а исправление даты автоматически убирает устаревшее предупреждение. `id` детерминирован и годится для стабильного ключа списка на клиенте.

## Важные ограничения

- Сервер использует локальную календарную дату Windows/хоста (`DateTime.Now`). Перед эксплуатацией нужно согласовать и закрепить часовой пояс сервера.
- Это API уведомлений, не фоновая служба и не готовый графический интерфейс. При открытии главного экрана клиент должен вызвать `/api/alerts`, показать список и подсветить ФИО сотрудников с `HighlightEmployeeName=true`.
- Для точного срока классности требуется заполнить `ReviewDueOn`. Автоматически придумывать дату следующей проверки нельзя.
- Нужны интеграционные испытания с PostgreSQL и сборка .NET 8; статические проверки не заменяют их.

## Проверка

Из корня проекта:

```powershell
python .\tests\check_stage10_alerts.py
```

После настройки PostgreSQL и миграций выполнить сборку проекта и запросить `GET /api/alerts` под каждой ролью. Проверить граничные даты: сегодня, через 30 дней, через 31 день; контракт ровно через шесть месяцев и через шесть месяцев плюс один день; классность аналогично. Затем изменить даты и убедиться, что предупреждения обновились без очистки таблиц — уведомления не хранятся в базе.
