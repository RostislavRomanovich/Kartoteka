# Этап 9 — редактирование связанных записей

## Что добавлено

Добавлены `PUT`-методы для редактирования существующих записей без создания новых строк:

- `PUT /api/employees/{employeeId}/details/cars/{recordId}`
- `PUT /api/employees/{employeeId}/details/license-categories/{recordId}`
- `PUT /api/employees/{employeeId}/details/relatives/{recordId}`
- `PUT /api/employees/{employeeId}/details/position-history/{recordId}`
- `PUT /api/employees/{employeeId}/details/classness-history/{recordId}`
- `PUT /api/employees/{employeeId}/details/awards/{recordId}`
- `PUT /api/employees/{employeeId}/details/business-trips/{recordId}`
- `PUT /api/employees/{employeeId}/details/messengers/{recordId}`

Все методы требуют политику `CanEditEmployees`, проверяют активность родительской карточки и ищут дочернюю запись одновременно по `recordId` и `employeeId`. Это предотвращает изменение записи через карточку другого сотрудника. Успешные изменения журналируются.

## Защита от дублирования

- При добавлении и редактировании госномер автомобиля нормализуется: удаляются пробелы и знаки пунктуации, буквы приводятся к верхнему регистру.
- Уникальный индекс PostgreSQL на `EmployeeCar.RegistrationPlate` защищает от совпадающих непустых номеров, в том числе при параллельных запросах.
- При редактировании категория прав, награда и контакт мессенджера проверяются на дубликат без сравнения записи с самой собой.
- При редактировании периода должности пересечения проверяются без сравнения записи с самой собой.

## Важные замечания

1. Уникальный индекс на номера автомобилей может не примениться, если в уже заполненной базе есть повторяющиеся номера. Перед миграцией такие строки нужно выявить и разрешить вручную. Для новой пустой базы это ограничение безопасно.
2. На уровне API проверка дубликатов возвращает `409 Conflict`. При гонке параллельных запросов уникальный индекс не позволит записать дубликат, однако единый middleware для преобразования всех `DbUpdateException` в `409` пока не добавлен.
3. Редактирование не меняет ID существующей записи и не выполняет удаление с последующим созданием.
4. В этом окружении отсутствует .NET SDK и PostgreSQL, поэтому компиляция и интеграционные тесты не запускались. Статические проверки не заменяют реальный запуск.

## Проверка исходников

Из корневой папки проекта запустить:

```powershell
python tests/check_stage9_updates.py
python tests/check_stage8_details.py
python tests/check_stage7_api.py
python tests/check_stage6_schema.py
```

Для рабочего сервера после получения .NET SDK следует собрать проект и применить миграцию, включающую уникальный индекс госномера, сначала к тестовой базе.
