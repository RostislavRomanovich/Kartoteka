# Этап 11 — веб-интерфейс уведомлений и просмотра карточек

## Что добавлено

- `wwwroot/index.html`, `styles.css`, `app.js`: адаптивный веб-интерфейс, который отдаётся тем же ASP.NET Core сервером.
- Форма входа использует `POST /api/auth/login`; JWT хранится только в памяти вкладки и не сохраняется в `localStorage` или `sessionStorage`.
- Панель уведомлений использует `GET /api/alerts`, показывает сроки, тип и статус предупреждения.
- ФИО выделяется жёлтым цветом, если сервер вернул `highlightEmployeeName=true` для сотрудника.
- Список и поиск сотрудников используют `GET /api/employees`; карточка — `GET /api/employees/{id}`.
- В карточке показаны уведомления, относящиеся к конкретному сотруднику.
- Кнопка обновления повторно запрашивает актуальные данные; API-запросы выполняются с `cache: no-store`.
- Интерфейс не использует `innerHTML` для данных API, а вставляет текст через `textContent`.

## Запуск

После запуска серверной части открой корневой адрес сервера в браузере. При настройке `UseHttpsRedirection` используй HTTPS-адрес, указанный в профиле запуска. Выполни вход действующей учётной записью. Никаких тестовых паролей в интерфейсе нет.

## Ограничения

- Это первый интерфейс для входа, уведомлений, поиска и чтения карточек, а не полный редактор всех полей.
- JWT находится только в памяти вкладки и исчезает при перезагрузке страницы; после обновления потребуется войти повторно. Это уменьшает риск сохранения токена в браузерном хранилище, но не заменяет HTTPS и общие меры защиты рабочего места.
- Дата отображается в формате `ДД.ММ.ГГГГ`.
- Веб-интерфейс использует существующие API и не обходит серверную авторизацию. Все права должны дополнительно проверяться сервером.

## Проверки

Запусти `python tests/check_stage11_ui.py` для статических проверок UI. Это не заменяет сборку .NET и тестирование с реальным PostgreSQL/браузером.
