# Этап 7 — API карточек сотрудников и подразделений

## Что реализовано в исходном коде

### Сотрудники (`/api/employees`)
- `GET /api/employees?q=...&page=1&pageSize=50` — поиск и постраничный список действующих карточек.
- `GET /api/employees/{id}` — просмотр карточки.
- `POST /api/employees` — создание карточки для `admin` и `editor`.
- `PUT /api/employees/{id}` — изменение действующей карточки для `admin` и `editor`.
- `DELETE /api/employees/{id}` — **архивация**, а не физическое удаление.
- `POST /api/employees/{id}/restore` — восстановление из архива для `admin` и `editor`.
- `includeArchived=true` разрешён только администратору.
- В DTO включены подразделение и поля воинского учёта/перевода, которые уже присутствуют в модели.
- Табельный номер нормализуется и проверяется на повторение; ограничение БД остаётся последней линией защиты от гонки параллельных запросов.
- Записи об архивации и восстановлении попадают в журнал аудита.

### Подразделения (`/api/organizational-units`)
- `GET /api/organizational-units` — список действующих подразделений.
- `GET /api/organizational-units/{id}` — получение подразделения.
- `POST /api/organizational-units` и `PUT /api/organizational-units/{id}` — только администратор.
- Проверяется существование активного родителя и предотвращаются циклы иерархии.
- Запрещается деактивация подразделения с действующими сотрудниками или активными дочерними подразделениями.

## Примеры запросов

### Создать сотрудника

```http
POST /api/employees
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "personnelNumber": "TEST-0001",
  "lastName": "Иванов",
  "firstName": "Иван",
  "middleName": "Иванович",
  "position": "Специалист",
  "organizationalUnitId": 1,
  "contractStart": "2026-01-15",
  "contractTermMonths": 12
}
```

### Поиск

```http
GET /api/employees?q=TEST-0001&page=1&pageSize=20
Authorization: Bearer <accessToken>
```

### Архивация и восстановление

```http
DELETE /api/employees/123
POST /api/employees/123/restore
```

Оба запроса требуют токен пользователя с ролью `admin` или `editor`. Архивация сохраняет карточку и связанные записи; физическое удаление через этот API не выполняется.

## Важно

- Пример `organizationalUnitId: 1` работает только если подразделение с таким ID действительно существует и активно.
- Это API-этап, а не готовый графический интерфейс.
- Сборка .NET и интеграционные тесты против PostgreSQL должны быть выполнены в Windows-среде с установленным .NET SDK и работающей БД.
- Перед рабочей эксплуатацией нужно проверить политики хранения/доступа к персональным и служебным сведениям, резервное копирование и HTTPS.
