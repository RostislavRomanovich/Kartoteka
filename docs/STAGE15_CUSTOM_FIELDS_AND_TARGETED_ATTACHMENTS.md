# Этап 15 — настраиваемые поля и вложения на уровне конкретной записи

## 1. Настраиваемые поля

Администратор может создавать определения полей для областей `employee` (сотрудник) и `relative` (родственник), менять подпись/тип/обязательность/порядок и деактивировать поле. Ключ и область после создания неизменяемы, чтобы не потерять связь с сохранёнными значениями. Деактивация скрывает поле из форм, но сохраняет старые значения.

Поддерживаемые типы: `text`, `date`, `number`, `boolean`, `select`. Для `select` на этом этапе сохраняется текстовое значение; список допустимых вариантов ещё не настраивается. Даты можно передавать как `ДД.ММ.ГГГГ` или `YYYY-MM-DD`. Значения проверяются сервером; один и тот же идентификатор поля нельзя повторить в одном запросе.

API:
- `GET /api/custom-fields?scope=employee|relative` — активные определения;
- `POST /api/custom-fields` — создать определение (admin);
- `PUT /api/custom-fields/{id}` — изменить подпись, тип, обязательность, сортировку (admin);
- `DELETE /api/custom-fields/{id}` — деактивировать (admin);
- `GET/PUT /api/employees/{employeeId}/custom-fields` — значения сотрудника;
- `GET/PUT /api/employees/{employeeId}/relatives/{relativeId}/custom-fields` — значения родственника.

Запись значений выполняется обновлением по уникальной паре владелец+определение. Это делает повторное сохранение идемпотентным и не создаёт повторных строк.

## 2. Вложения привязаны к записи

У вложения теперь есть `TargetType` и `TargetId`:
- `employee` + `0` — документ всей карточки сотрудника;
- `relative`, `car`, `license-category`, `position-history`, `classness`, `award`, `trip`, `messenger` + ID существующей связанной записи — вложение конкретной записи.

В интерфейсе администратора рядом с каждой группой документов есть выбор целевой записи и кнопка «Добавить скан». Например, скан СТС можно прикрепить к конкретному автомобилю, а свидетельство о рождении — к конкретному родственнику. К одному документу/группе по-прежнему относится один список файлов, а не отдельная кнопка у каждого поля.

Сервер проверяет, что выбранная запись существует и принадлежит тому же сотруднику. Уникальность одинакового файла проверяется по сотруднику, группе документа, типу/ID целевой записи и SHA-256. Одинаковый файл можно использовать в другой группе или прикрепить к другой связанной записи, если это действительно отдельный экземпляр документа.

## 3. Миграция базы

Не удаляйте и не пересоздавайте базу. После предыдущей миграции Stage14 выполните из корня проекта:

```powershell
dotnet ef migrations add Stage15CustomFieldsAndAttachmentTargets
dotnet ef database update
dotnet build
```

Новая миграция добавит `TargetType` и `TargetId` к вложениям с безопасными значениями по умолчанию (`employee`, `0`), что сохраняет существующие вложения как документы уровня сотрудника. Также обновится уникальный индекс и добавится проверка допустимого типа цели.

Перед применением на рабочей базе обязательно сделайте резервную копию PostgreSQL и проверьте сгенерированный файл миграции. Не применяйте миграцию к рабочим данным, пока она не проверена на отдельной тестовой копии.

## 4. Проверка

Статические проверки:

```powershell
python tests/check_stage15_custom_fields_and_targets.py
python tests/check_stage14_attachments.py
```

После установки .NET SDK и PostgreSQL дополнительно:
1. Выполнить `dotnet build`.
2. Применить миграцию на тестовой базе.
3. Создать поле сотрудника и родственника, сохранить значения, повторить сохранение и проверить, что не возникли дубли.
4. Деактивировать поле и убедиться, что значение осталось в БД, но поле не показывается в форме.
5. Прикрепить тестовый файл к конкретному автомобилю/родственнику, убедиться, что файл виден только для выбранной цели.
6. Попробовать прикрепить файл к ID записи другого сотрудника — сервер должен отклонить запрос.
7. Проверить, что `editor` и `viewer` не имеют доступа к API вложений, согласно действующему правилу `AdminOnly`.

## Ограничения этапа

- Реальные C#-сборка и PostgreSQL-интеграционные тесты в текущей среде не запускались.
- Для `select` пока нет редактируемого списка вариантов; поле сохраняет текст.
- Настраиваемые поля родственников доступны через форму родственника. Файловые вложения пока доступны только администраторам, как и было задано ранее.
- Антивирусное сканирование вложений и внешнее файловое хранилище остаются отдельными задачами перед промышленным развёртыванием.
