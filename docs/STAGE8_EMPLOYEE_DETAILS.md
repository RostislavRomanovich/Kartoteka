# Этап 8 — связанные записи карточки сотрудника

## Назначение

Добавлен первый API-слой для управления связанными записями карточки: транспортом, категориями водительского удостоверения, родственниками, историей должностей, классностью, наградами, командировками и контактами в мессенджерах.

## Endpoints

Все endpoints требуют JWT-аутентификацию.

- `GET /api/employees/{employeeId}/details` — сводка связанных записей действующего сотрудника.
- `POST /api/employees/{employeeId}/details/cars`
- `POST /api/employees/{employeeId}/details/license-categories`
- `POST /api/employees/{employeeId}/details/relatives`
- `POST /api/employees/{employeeId}/details/position-history`
- `POST /api/employees/{employeeId}/details/classness-history`
- `POST /api/employees/{employeeId}/details/awards`
- `POST /api/employees/{employeeId}/details/business-trips`
- `POST /api/employees/{employeeId}/details/messengers`
- `DELETE /api/employees/{employeeId}/details/{kind}/{recordId}` — удаление связанной записи, где `kind` — одно из: `cars`, `license-categories`, `relatives`, `position-history`, `classness-history`, `awards`, `business-trips`, `messengers`.

Изменение связанных записей разрешено ролям `admin` и `editor`; `viewer` может читать. Перед удалением сервер проверяет, что запись действительно принадлежит указанному сотруднику. Удаление связанной записи физическое, в отличие от архивации карточки сотрудника; операция фиксируется в журнале аудита.

## Примеры JSON

Автомобиль:

```json
{
  "makeModel": "Lada Vesta",
  "registrationPlate": "А123АА198",
  "productionYear": 2022,
  "registrationCertificateNumber": "99 00 123456"
}
```

Родственник:

```json
{
  "fullName": "Иванов Иван Иванович",
  "relationship": "сын",

  "workplace": null,
  "position": null,
  "schoolOrInstitution": "Школа № 10",
```

```json

  "expiresOn": "2027-05-14"
}
```

## Защита от дублирования и валидация

- Повторяющийся номер автомобиля в пределах одной карточки отклоняется.
- Повторная категория водительского удостоверения отклоняется.
- Пересекающиеся периоды истории должностей отклоняются.
- Повтор награды с тем же типом, названием и датой отклоняется.
- Повтор контакта одного мессенджера отклоняется.
- Все операции изменения привязаны к `employeeId`, а идентификатор дочерней записи дополнительно проверяется на принадлежность сотруднику.

Проверки на уровне API не заменяют уникальные ограничения базы данных: при параллельных запросах часть дублирующих операций всё ещё должна быть защищена ограничениями БД и обработкой `DbUpdateException`. Это отдельная задача последующего усиления.

## Ограничения этапа

- В этом этапе есть чтение сводки, добавление и удаление связанных записей; полноценное редактирование существующих дочерних записей будет отдельным шагом.
- Вложения и фотографии не возвращаются в сводке; доступ к ним остаётся через отдельный контроллер вложений.
- `messengerContactsJson` пока передаётся как строковое поле; строгая проверка JSON-схемы не добавлена.
- Статические тесты проверяют наличие ключевых конструкций в коде, а не фактическую работу API.
- Компиляция C# и интеграционные тесты PostgreSQL в текущей среде не выполнены.
