# Этап 3 — первый запуск на Windows

## Что подготовлено

- `scripts/windows/Prepare-Local.ps1` проверяет наличие .NET SDK, восстанавливает NuGet-пакеты, при отсутствии создаёт EF Core-миграцию `InitialCreate`, применяет миграции, собирает проект и запускает API.
- `scripts/windows/Test-Api.ps1` проверяет health endpoint, вход администратора и чтение списка сотрудников.
- Исправлена выборка сотрудников: преобразование DTO выполняется после загрузки сущностей, а не внутри SQL-запроса EF Core.
- Добавлена серверная проверка диапазона срока контракта.

## Требования

1. Windows PowerShell 7 предпочтителен (скрипт проверки использует `-SkipCertificateCheck`).
2. .NET 8 SDK.
3. PostgreSQL 14+ запущен и доступен по сети.
4. Создана пустая база `kartoteka` и пользователь приложения с правами на создание/изменение таблиц в этой базе. Для production не следует запускать приложение под суперпользователем PostgreSQL.
5. Доступ к NuGet при первом восстановлении пакетов.

## Запуск

Из каталога `kartoteka_server_stage1` откройте PowerShell и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\windows\Prepare-Local.ps1
```

При запросе укажите строку подключения PostgreSQL. Пример формата:

```text
Host=localhost;Port=5432;Database=kartoteka;Username=kartoteka_app;Password=ВАШ_ПАРОЛЬ
```

Задайте пароль первого администратора. Скрипт создаёт случайный ключ подписи JWT только в переменной текущего процесса; не используйте этот ключ для постоянной production-установки. При повторном запуске с уже существующей учётной записью пароль администратора не сбрасывается автоматически.

После запуска в другом окне PowerShell проверьте порт/URL, показанный приложением, затем выполните, например:

```powershell
.\scripts\windows\Test-Api.ps1 -BaseUrl 'http://localhost:5080' -Email 'admin@localhost'
```

Сценарий запускает API на `http://localhost:5080` только для локальной первичной проверки. Не публикуйте этот HTTP endpoint в локальную сеть или интернет и не используйте такую конфигурацию в production. Перед сетевым развёртыванием необходимо настроить HTTPS, секреты и сетевые ограничения.

## Что не считать готовым

Это этап первого запуска API, а не готовая к эксплуатации система. Пока не подтверждены запуск на целевом ПК, полный набор ролевых тестов, резервное копирование/восстановление, политика хранения персональных данных, антивирусная проверка вложений и перенос старой базы в целевые таблицы. Скрипт импорта `migration/snapshot_to_postgres.py` сохраняет исходные строки в промежуточную схему `legacy_import`; он не завершает бизнес-конвертацию данных в целевую модель.
