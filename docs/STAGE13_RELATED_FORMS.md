# Этап 13 — подразделения и связанные записи

## Реализовано в интерфейсе
- Выбор активного подразделения из иерархического справочника `GET /api/organizational-units`; `organizationalUnitId` передаётся в основной API сотрудника.
- Просмотр, добавление, редактирование и удаление автомобилей, водительских категорий, родственников, истории должностей, классности, наград, командировок и мессенджеров.
- Редактирование отправляет `PUT` на ID существующей записи; добавление использует `POST`; удаление — типизированный `DELETE`.
- Даты вводятся в `ДД.ММ.ГГГГ` и преобразуются в ISO перед отправкой. Проверяются обязательные поля и основные диапазоны дат.
- Доступ к кнопкам редактирования ограничен ролями `admin` и `editor`; серверная авторизация остаётся обязательной.
- Списки формируются через `textContent`, а не через HTML из данных пользователя.

## Проверка
Запустить статические проверки: `python tests/check_stage13_related_ui.py`. Они не заменяют `dotnet build` и интеграционные тесты PostgreSQL.

## Ограничения
- Выбор подразделения позволяет выбрать только активные подразделения. Текстовое поле дополнительного обозначения подразделения сохранено для совместимости.
- Контакты мессенджеров родственников сохраняются как текстовое поле, потому что текущий серверный контракт принимает `MessengerContactsJson`; интерфейс не пытается автоматически интерпретировать JSON.
- На данном этапе серверная сборка и реальная работа с PostgreSQL не подтверждены в этой среде.
