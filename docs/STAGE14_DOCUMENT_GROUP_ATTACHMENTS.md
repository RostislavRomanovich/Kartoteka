# Этап 14 — документы и сканы, сгруппированные по документу

## Правило группировки
Вложение относится к документу/группе полей, а не к отдельному полю. Например, один скан паспорта имеет категорию `passport` и относится к серии, номеру, дате и органу выдачи одновременно. При добавлении новых групп используется тот же универсальный механизм: ключ группы, заголовок, список файлов и одна кнопка «Добавить скан» рядом с заголовком.

Поддерживаемые группы:
- `passport` — паспорт;
- `military_id` — военный билет;
- `access` — документы допуска;
- `contract` — контракт;
- `driving_license` — водительское удостоверение;
- `car_registration` — документы на автомобиль;
- `birth_certificate` — свидетельство о рождении;
- `award` — наградные документы;
- `personal_feature` — фотографии особых примет;
- `relative` — документы родственников;
- `other` — прочие документы.

Группы представлены универсальным списком в UI и allow-list на сервере. Это предотвращает произвольные категории, но позволяет добавлять новые категории централизованно без кнопки на каждое поле.

## Поля паспорта
Добавлены серия, номер, кем выдан и дата выдачи паспорта в сущность, DTO, API и форму сотрудника. Скан прикрепляется отдельно один раз к группе `passport`.

## Безопасность файлов
- Доступ к списку, загрузке, скачиванию и удалению вложений разрешён только `admin` (сохраняет заданное ранее правило доступа к файлам/фотографиям).
- Максимальный размер — 10 МБ.
- Разрешены только PDF, JPEG, PNG и WEBP; сервер проверяет сигнатуру содержимого и соответствие расширению.
- SHA-256 хранится для каждого файла. Повторное прикрепление того же содержимого к той же группе одного сотрудника отклоняется как конфликт. Уникальный индекс PostgreSQL защищает также от параллельных запросов.
- Имя файла очищается до имени без пути; при скачивании добавляется `X-Content-Type-Options: nosniff`.
- Загрузка, скачивание и удаление журналируются.
- Перед промышленной эксплуатацией рекомендуется антивирусная проверка файлов и резервное копирование базы.

## Миграция
Так как добавлены четыре поля паспорта и уникальный индекс вложений, для уже созданной базы нужно создать и применить новую EF Core migration. Из корня проекта:
`dotnet ef migrations add Stage14PassportAndAttachmentGroups`
затем:
`dotnet ef database update`

Не удаляйте старую базу и не пересоздавайте её для применения этого этапа.

## Проверка
Запустить `python tests/check_stage14_attachments.py` для статических проверок. Затем на Windows с .NET SDK и PostgreSQL выполнить `dotnet build`, применить миграцию и проверить вход под `admin`: загрузить тестовый PDF/PNG, скачать, удалить, повторно загрузить тот же файл и убедиться, что сервер отвечает конфликтом. Также проверить, что `editor` и `viewer` получают отказ в доступе к API вложений.

Статические проверки не заменяют сборку и интеграционные тесты.
