# Этап 4 — управление учётными записями и проверка ролей

## Что добавлено

- `POST /api/admin/users` — администратор создаёт учётную запись с одной ролью `admin`, `editor` или `viewer`.
- `GET /api/admin/users` — список учётных записей без паролей и хэшей.
- `PUT /api/admin/users/{id}/role` — смена роли.
- `PUT /api/admin/users/{id}/active` — активация/деактивация.
- Изменения пользователей записываются в журнал аудита.
- Запрещено деактивировать собственную учётную запись, снимать с себя роль администратора и оставлять систему без активного администратора.
- `scripts/windows/Test-Roles.ps1` — проверка сценариев `admin/editor/viewer` на запущенном API.

## Проверка после успешного этапа 3

1. Оставьте сервер запущенным в первом окне PowerShell.
2. Во втором окне из каталога проекта выполните:

   ```powershell
   .\scripts\windows\Test-Roles.ps1
   ```

3. Введите пароль администратора. Скрипт создаёт временных пользователей и тестовую карточку, проверяет разрешённые и запрещённые действия, затем деактивирует временные учётные записи и удаляет тестовую карточку.
4. Если команда завершилась ошибкой, сохраните полный вывод и не используйте тестовые данные как реальные.

## Ограничения и меры предосторожности

- Этот этап добавляет API управления пользователями, а не графический административный интерфейс.
- Ролевые изменения могут оставаться в уже выданном JWT до истечения его срока (20 минут). Для чувствительных рабочих сред следующим улучшением должна стать проверка статуса пользователя/версии безопасности при каждом запросе или короткоживущие токены с механизмом отзыва.
- Проверка «последнего администратора» защищает обычные последовательные операции, но не является полноценной защитой от одновременных административных запросов.
- Перед рабочим использованием необходимы HTTPS, резервное копирование, ограничение доступа к PostgreSQL, аудит экспорта, проверка типов файлов и антивирусная проверка вложений, тесты на реальной БД и проверка требований к персональным данным.
- C# сборка и тестирование PostgreSQL в среде подготовки не выполнялись. Успешность кода не утверждается до запуска `dotnet build` и `Test-Roles.ps1` на целевой машине.
